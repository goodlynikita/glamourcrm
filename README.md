# GLAMOUR CRM

Демонстрационный веб-кабинет сети маникюрных студий. Встроенные клиенты, сотрудники, филиалы, визиты и суммы вымышлены.

## Запуск

```sh
python3 -m http.server 8000 --directory dist
```

Откройте [http://localhost:8000](http://localhost:8000). Сборка и установка зависимостей не нужны.

Демопрофиль переключается в нижней части бокового меню. Фильтр филиала применяется ко всем разделам. Администратор начинает с очереди контактов, руководитель — с денежной панели. Файлы CSV, XLSX и XLS импортируются в браузере с предпросмотром. Шаблон CSV доступен в разделе импорта.

## Как работать с воронкой

1. Назначьте обзвон по филиалу или откройте демоочередь. Кнопка «Результат» сохраняет звонок и следующий шаг.
2. После контакта отметьте результат. Для повторного звонка укажите срок. Для записи заполните дату, время и плановую сумму. Все записи отображаются в недельном расписании.
3. После состоявшегося визита укажите фактическую оплату и дату. Клиентская карточка покажет оплату и последнюю подтверждённую дату визита.
4. Если визит не состоится, закройте запись с причиной. Когда появится новый повод для контакта, можно добавить клиента снова.

### Денежные показатели

- **Выручка по воронке** суммирует фактические оплаты по дате получения за выбранный период.
- **Ближайшие записи** суммируют плановые цены записей на ближайшие 7, 30 или 90 дней включительно с сегодняшнего дня. Просроченные визиты видны в списке следующих действий.
- **Потенциал до записи** суммирует известные оценки на этапах «Связаться» и «Есть интерес». Оценки без суммы выводятся отдельным количеством.
- **Средний чек** делит фактическую выручку на количество оплаченных визитов за период.

Задачи, импорт и изменения в воронке сохраняются в localStorage. Демопрофили работают в пределах одного браузера. При обновлении с первой версии сохраняются задачи и клиенты, а существующие записи появляются в воронке с неизвестной ценой. Дата регистрации и дата будущей записи остаются отдельными полями. Даты рассчитываются по московскому времени.

## Подключение API «Малахита»

В `dist/repository.mjs` находится граница хранения с методами `read()` и `dispatch(command)`. `dist/model.mjs` определяет рабочие команды и схему данных, `dist/finance.mjs` содержит правила учёта и расчёта денежных показателей, а `dist/importer.mjs` переводит табличные строки в те же поля. В будущем серверный адаптер сможет выдавать нормализованные данные, хранить записи по филиалам, сопоставлять внешние идентификаторы и использовать завершённые посещения и подтверждённые оплаты из API. Секреты API и контроль доступа относятся к серверу.
