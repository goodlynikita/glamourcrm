# GLAMOUR CRM

[Открыть демо на GitHub Pages](https://goodlynikita.github.io/glamourcrm/)

Загрузите CSV, XLSX или XLS через «Импорт». Тестовый CSV доступен там же. После загрузки откроется «Деньги в базе» с оценкой возврата, приоритетными клиентами, очередью и подтверждёнными оплатами. Демо использует вымышленные данные и сохраняет изменения в браузере.

## Как считается потенциал

На клиента приходится оценка одной покупки. Приложение использует средний чек из файла, общую сумму оплат на число визитов либо последнюю оплату. При отсутствии данных может использовать медиану чеков по филиалу при совпадении последней услуги и минимум трёх клиентах с известной суммой. Остальные клиенты остаются в списке с пометкой «Нет оценки». Дата регистрации хранится отдельно от посещений.

Филиал и ID или телефон определяют, какую карточку обновить. Повторная загрузка сохраняет историю задач и контактов. Пустые денежные ячейки сохраняют ранее загруженные суммы.

Очередь показывает одного клиента с причиной контакта и подсказкой по возражению. Отметки полезности меняют порядок подсказок внутри филиала. Потенциал и подтверждённые оплаты отображаются отдельно. Фактическую сумму и дату сотрудник вносит после подтверждения платежа. Автоматического контакта с клиентами в приложении нет.

## Сервер

Для локальной проверки требуется Node.js 24+.

```sh
node server/index.mjs --demo
node --test tests/*.mjs
```

Демо-сервер доступен на [127.0.0.1:8787](http://127.0.0.1:8787). Логины `manager`, `alina`, `maria`, `sofia`, пароль `glamour-demo`. Для рабочей базы запустите без `--demo` и задайте `GLAMOUR_USERS_JSON` со своими паролями от 12 символов, `GLAMOUR_DB` с отдельным путём к SQLite и `GLAMOUR_HTTPS=1` при размещении за HTTPS-прокси. Руководитель видит сеть, администраторы получают данные своих филиалов.

Для рекомендаций языковой модели задайте на сервере `GLAMOUR_AI_KEY`. Модель настраивается через `GLAMOUR_AI_MODEL`, по умолчанию `gpt-4.1-mini`. OpenAI получает обезличенные показатели по сегментам. Файлы, карточки и комментарии остаются в CRM. Денежные суммы всегда рассчитывает приложение. Публичная демонстрация использует локальные правила анализа и помощника.

`dist/repository.mjs` работает с браузерным и серверным хранилищем. Будущий адаптер «Малахита» может передавать нормализованные данные в существующую операцию импорта.
