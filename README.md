# GLAMOUR CRM

Веб-приложение для возврата клиентов сети GLAMOUR. [Публичное демо](https://goodlynikita.github.io/glamourcrm/)

## Публичная демонстрация

Используйте вымышленные имена, идентификаторы и номера в формате `+7 (000) …`. На GitHub Pages роли имитируются через меню профиля. Состояние хранится в браузере. Для сквозной проверки с настоящей авторизацией запустите серверный режим.

1. Под руководителем откройте «Импорт данных» и скачайте тестовый CSV.
2. Загрузите файл, проверьте сопоставление столбцов и сохраните базу.
3. В «Клиентах» нажмите «Назначить обзвон». Выберите филиал, сегмент, администратора и срок.
4. Переключитесь на этого администратора, откройте клиента или кнопку «Результат» в очереди. Сохраните результат и следующий шаг.
5. Под руководителем откройте «Панель руководителя». Сегменты и сроки задач доступны в «Настройках». Там же можно сбросить демо.

Повторный импорт сопоставляет клиентов внутри филиала по ID и телефону. Колонки, которых в файле нет, сохраняют прежние значения. Пустые ячейки в сопоставленных полях визитов, записей и количества очищают соответствующий факт. Пустые ID и телефон сохраняют значение найденной карточки. История звонков, задачи и запрет связи сохраняются.

## Серверный режим

Нужен Node.js 24+. Установка зависимостей не требуется.

```sh
node server/index.mjs --demo
```

Откройте [http://127.0.0.1:8787](http://127.0.0.1:8787). Логины `manager` (руководитель), `alina`, `maria`, `sofia` (администраторы), пароль для демонстрации `glamour-demo`.

Сервер хранит базу, задачи, настройки и сессии в SQLite. Руководитель видит сеть, администратор получает только данные назначенных филиалов и может фиксировать результаты своих задач. Проверка выполняется для чтения и команд. По умолчанию сервер слушает localhost. Для запуска с пустой базой задайте свои пароли через `GLAMOUR_USERS_JSON` (JSON вида `{"manager":"…","alina":"…"}`, минимум 12 символов) и запустите без `--demo`. Используйте отдельный файл базы через `GLAMOUR_DB`, чтобы разделить демонстрационные и рабочие данные. Для удалённого доступа нужен HTTPS на прокси и `GLAMOUR_HTTPS=1`. На этапе эксплуатации отдельно настройте развёртывание, резервирование и доступ к персональным данным.

## Проверка

```sh
node --test tests/smoke.mjs
```

В `dist/model.mjs` и `dist/retention.mjs` находятся правила сегментации и операции. `dist/repository.mjs` переключает локальное и серверное хранение. `server/access.mjs` проверяет права. В будущем адаптер выгрузки «Малахита» сможет подавать нормализованные строки в ту же операцию импорта.
